# 倒计时停止、超时负向计时设计

## 背景

当前 `time` 倒计时在到达 `00:00` 后会停止，只保留红色提醒，并在一分钟后自动解除提醒。用户需要在计时期间随时停止，并在没有及时停止时继续看到超时的实际长度，停止后能知道本次完整用时。

## 目标

- 倒计时运行时，在顶部工具栏持续显示醒目的状态颜色。
- 运行中的计时器提供明确的“停止”按钮。
- 倒计时到零后不自动停止，而是显示负向计时，例如 `−00:01`、`−02:18`。
- 到零时保留现有提示音和视觉提醒，且超时状态持续到用户停止。
- 用户停止后停止计时、清除告警样式，并通过消息面板提示完整用时；提示包含正常计时和超时部分。
- 停止后可以直接重新设置分钟数并开启下一次计时。

## 方案

采用当前单页结构内的轻量计时状态扩展，并把无 DOM 的时间计算放进独立的 `timer.js`，便于测试和复用。

计时状态包含：

- `durationSec`：用户设定的目标秒数。
- `timeLeftSec`：距离目标的秒数，可为负值。
- `startedAt`：开始时间戳，用于让页面被后台节流后恢复时仍能追上真实时间。
- `timerInterval`：只负责定期刷新界面；实际剩余时间根据时间戳计算。

状态转换为：

1. **未运行**：显示分钟输入和 `time` 按钮。
2. **运行中**：隐藏输入，显示剩余时间；工具栏使用琥珀色强调，按钮显示“停止”。最后 60 秒保留更强的橙色提示。
3. **超时**：`timeLeftSec` 小于零，显示带负号的 `−MM:SS`；工具栏、编辑区边框和品牌使用红色，达到零的瞬间播放一次提示音。
4. **用户停止**：按 `durationSec - timeLeftSec` 计算完整用时；提前停止时得到已经过的正常用时，超时后自动体现为目标时长加超时长度。随后清理计时器和告警样式，恢复可编辑的分钟输入，并调用消息面板显示结果。

`fmtTime` 会对正数和负数分别格式化，负值使用 Unicode 负号，分钟部分不截断，因此超过一小时也能继续显示。用户点击停止和到时后的负向计时共用同一个刷新路径，避免到时后产生第二个计时器或自动清理状态。

## 视觉与交互

- 运行中：时间数字使用琥珀色，计时容器增加浅琥珀背景和边框；停止按钮使用红色实心样式。
- 超时：时间数字、品牌和计时容器使用红色；编辑区沿用当前告警边框动画，提示音只在首次进入超时时播放。
- 停止后：计时容器回到普通样式，消息面板显示“完整用时：X 分 Y 秒”，如果发生超时同时显示“含超时 Z 分 W 秒”。
- 重新开始时清除上一轮的面板告警和超时状态，重新从输入分钟数开始计时。

## 错误与边界

- 分钟输入继续限制在 1 到 999，非法值回退到 15 分钟。
- 页面切换到后台导致 `setInterval` 降频时，使用 `Date.now()` 计算实际经过时间，回到页面时立即显示正确状态。
- 停止按钮重复点击不会产生多个结果，因为停止后按钮恢复为 `time`，且计时器引用已清空。
- 计时状态不写入草稿内容或加密存储；刷新页面后不恢复上一轮计时，避免后台计时造成误导。

## 测试策略

- 用 Node 内置测试覆盖分钟输入归一化、正向格式化、负向格式化、完整用时计算和到零边界。
- 在浏览器中验证运行中颜色与停止按钮、超时负向计时、停止后的完整用时提示，以及重新开始时状态清理。
- 运行现有页面的语法检查和新增 Node 测试。
